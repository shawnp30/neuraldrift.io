# Running FastH3 8-Step V2 (MiniMax H3 Distilled) — Current Status

This guide covers **FastVideo's FastH3 8-Step V2**, a distilled version of MiniMax-H3 that
replaces its diffusion transformer with an 8-step student model trained via DMD2 distillation
and VSA-H3 sparse attention. It is a real, officially released model — but as of this writing
it is **not a practical local install on a single 16GB consumer GPU**, including NeuralDrift's
own RTX 5080 Lab machine. This guide explains exactly why, what it would actually take, and
what to run instead today.

Full sourcing, the GPU compatibility matrix, and the base-H3 comparison table live on the
[NeuralDrift Lab writeup](/lab/fasth3-8-step-v2) — this guide is the practical companion to
that page.

## Before you start: is this the model you actually want?

There is more than one "fast MiniMax H3" project, and they are easy to confuse:

- **FastH3 8-Step V2** (this guide) — built by FastVideo / Hao AI Lab @ UCSD. Replaces H3's
  transformer with a student model. Requires FastVideo's own VSA-H3 attention backend.
  Text-to-video + synchronized audio only — no image-to-video, no first/last-frame, no
  reference-to-video.
- **MiniMax H3 Turbo** — a separate project by the Lightx2v and ModelTC teams, distributed as
  a LoRA on top of the existing base H3 checkpoint. Community reporting describes it running
  with native ComfyUI support and no custom node required, including an 8-step
  reference-to-video variant. NeuralDrift has not tested this either, but it is architecturally
  a much smaller lift than FastH3 8-Step V2 — see [Related projects](#related-projects) below.

If your goal is "the fastest thing I can actually get running in ComfyUI today," the Turbo LoRA
is the more realistic starting point. If your goal is specifically FastVideo's FastH3 release,
keep reading.

## Prerequisites

FastH3 8-Step V2 is **not a drop-in ComfyUI checkpoint**. Its own model card states it requires
FastVideo's VSA-H3 attention backend, which is separate from stock ComfyUI's attention
implementations and from the unrelated "Patch Sage Attention" node used for other MiniMax H3
speedups. There is no official Comfy-Org workflow template for it — the official
[ComfyUI MiniMax H3 guide](https://docs.comfy.org/tutorials/video/minimax/minimax-h3) covers
only the base model and does not mention FastH3.

What the official release documents:

- **Backend:** FastVideo's VSA-H3 CUDA kernels, installed via `uv` per FastVideo's own
  documented path.
- **CUDA:** CUDA 13 toolchain in the tested install path.
- **GPU architecture:** NVIDIA Blackwell. Reference speedup numbers are measured on B200
  datacenter GPUs (single- and multi-GPU), not consumer cards. The RTX 5080 is Blackwell
  architecture, but that alone does not confirm the backend runs on it — NeuralDrift has not
  attempted that install.
- **Disk / VRAM:** the model card discloses 35B parameters in BF16. That alone is roughly
  35B × 2 bytes ≈ **70GB** for the transformer weights — before the VAE, text encoder, and audio
  components. No official minimum-VRAM figure has been published. This is why it does not fit
  a 16GB card: even in the best case, 70GB of weights cannot be resident in 16GB of VRAM without
  a quantization or offload scheme, and no such scheme has been published for this specific
  release (see [What doesn't exist yet](#what-doesnt-exist-yet)).

## What doesn't exist yet

The earlier, separate **FastH3 4-Step Preview v1** has a community GGUF quantization
([realrebelai/FastH3_GGUFs](https://huggingface.co/realrebelai/FastH3_GGUFs)) that streams
weights from system RAM and needs its own custom-compiled ComfyUI attention node — itself a
30–60 minute build requiring Visual Studio 2022 and CUDA 12.8+. That quantization is for the
4-step model, **not** the 8-Step V2 covered here. As of this writing, no GGUF or other
consumer-VRAM-scale quantization of FastH3 8-Step V2 was found.

## If you have the hardware to actually try it

If you have access to a Blackwell datacenter GPU (or several) with enough VRAM headroom, the
starting point is FastVideo's own repository and the official model card:

- [FastVideo/FastVideo-FastH3-8-Step-V2 on Hugging Face](https://huggingface.co/FastVideo/FastVideo-FastH3-8-Step-V2)
- [Hao AI Lab's FastH3 technical writeup](https://haoailab.com/blogs/fasth3-preview/)

Follow their documented install path directly (`uv`, VSA-H3 backend) rather than attempting to
wire the checkpoint into stock ComfyUI — the model card is explicit that it is not a drop-in
replacement.

## What to run today instead

**Base MiniMax-H3** already has native ComfyUI support and official Comfy-Org templates, and
NeuralDrift's Lab machine already has the Ref2VA checkpoint installed locally. It supports
text-to-video, image-to-video, first/last-frame, and reference-to-video — all capabilities
FastH3 8-Step V2 does not have in this release. Start with the
[official ComfyUI MiniMax H3 guide](https://docs.comfy.org/tutorials/video/minimax/minimax-h3)
if you want synchronized video+audio generation working locally today.

If you specifically want a local NVIDIA video+audio workflow that NeuralDrift has actually
execution-tested end to end, the catalog's AnimateDiff and ACE-Step 1.5 audio workflows have
current, successful RTX 5080 records — see [NeuralDrift Lab](/lab) for the full evidence index.
